# 命名与还原方法

本文说明工程化版是如何从 Ghidra 的反编译文本（`原始反编译结果/991CN X.ghidra原始.c`）
和反汇编（`原始反编译结果/991CN X.汇编.txt`）得到 `src/`、`include/`、`docs/` 的。

## 1. 流水线

```
parse.py        切分 Ghidra C 文本 → 函数列表（只在花括号深度 0 处认函数声明）
align.py        把 C 函数与反汇编函数入口按名称/地址对齐
index_build.py  生成 index.json（地址、参数、调用关系、RAM 引用、函数体）
naming_db.py    命名库：FUNCS[地址] = (新名, 返回类型, 参数表, 说明, 置信度, 标签)
                GLOBALS['地址'] = (新名, 类型, 说明)
build_project.py 重写函数、替换全局名、按模块拆分源文件、生成头文件与文档
```

## 2. 命名置信度

| 级别 | 依据 |
|------|------|
| `verified` | 逐指令核对（如 DAA/ADDC 链、寄存器搬运、唯一入口/调用点），或由常量块直接确认 |
| `strong` | 由调用者、数据结构、RAM 地址约定强确定，个别细节（如参数类型）可能有偏差 |
| `likely` | 由同族函数、常量结构、调用顺序推断，名称可能与原机符号不完全一致 |

每条 `note` 都写了判定依据；`docs/函数索引.md` 与每个函数头部的 `@note` 同步。

## 3. 关键还原结论

### 3.1 BCD 浮点寄存器组

由 `0x1DA06` 的 `dec_copy`（`LEA [param_2]` / `SA` 连续 10 字节）与 `0x1AF14`
直接写入 `0x6197723675790101` 的常数块相互印证，DECIMAL 库使用四个 10 字节寄存器：

| 寄存器 | 地址 | 用途 |
|--------|------|------|
| X | `0xD000..0xD009` | 主累加器（输入 A / 输出） |
| Y | `0xD010..0xD019` | 辅助操作数 |
| Z | `0xD030..0xD039` | 第三操作数 |
| W | `0xD050..0xD059` | 返回槽 |

首 2 字节为类型/符号（`0x10`=负、`0x80`=尾数全零、`>9`=特殊值），接着 7 字节尾数，
末 2 字节为指数。`0xD01E` 是运算操作码，`0xD01F` 是运算阶段。

### 3.2 十进制数学库入口（`decm_*`，标签 `float`）

`0x1CD78..0x1CE3C` 是 11 个薄封装，每个先 `ST XR0=>0xD05C` 再以 `R4`, `R5` 两个
操作码调用 `0x1CE4E`。由 R5 的取值（9/10/11）与 0x1CE4E 内部的行为可得：

- `R5=11`：加减法（`decm_add`），`0x1CE4E` 按阶段 `0xD01F` 调用 `0x1AB54`
  （<9，错位对齐）或 `0x1AC2C`（==9，带进位对齐）；
- `R5=9`：乘方族，`0x1CF90`（6=乘方）、`0x1C86C`（档位核心）、`0x1CDF6/0x1CE08/0x1CE1A`；
- `R5=10`：三角函数族 `0x1CACE`（sin）、`0x1CAE2`（cos）、`0x1D246`（tan，R4=2）；
- `0x1CF68`（8=除法）、`0x1CF28`（log）、`0x1CF0C`（ln）、`0x1C95E`（10^x）：
  分别为 `decm_div`、`decm_log10`、`decm_ln`、`decm_exp10`。

### 3.3 乘方/开方公共序列

`0x1CAA6` 装载 X←*a 后调用 `0x19B28`（注释为 `xln x`）再按 `0xD01F` 选择
`e^x`（`0x1B1E8`）或乘方核心（`0x1B1CA` 等），对应 `decm_power_common`。

### 3.4 nX-U8 “墓碑”函数

`0x2196A`（R1=0；`ADD ER0,ER8`）与 `0x21970`（R3=0；`ADD ER2,ER8`）只做
“测试/清零一个内存位”并立即返回。Ghidra 看不到数据流，把前者写成
`(ushort)param_1 + unaff_ER8`，把后者写成空函数。二者合计约 90 处 BL 调用，
命名为 `nxsb_test` / `nxsb_clear`。

### 3.5 0x022A8C 的活名

`0xD968`、`0xD544` 中调用 `FUN_rom_022a8c`、`FUN_rom_00d968` 的文本**插入了
`stat_analysis`、`mode_06_stat_loop` 等活名**；这两个名字在 `原始反编译结果/991CN X.ghidra原始.c`
中并不存在。因此生成器把这两个函数体按“实参个数 = 0”处理，以免与命名库冲突。

## 4. 生成期自动修正

- **合并的函数**：Ghidra 把子入口写进前一函数体（花括号不平衡）。`parse.header_at_top`
  只在深度 0 处认函数声明，因此 `0x1F12E`、`0x22006`、`0x23BD6` 之后的函数不再被吞掉；
  被吞掉的子入口在 `src/` 中以 `@addr` 注释保留。
- **调用点的实参补充**：Ghidra 常漏写寄存器实参。`build_proto_table` 取每个函数所有
  调用点实参数的最大值作为原型参数个数，`_walk_code` 在调用点补 `(uintptr_t)0`
  占位；`0` 参函数（`nxsb_clear`、`key_repeat_start` 等）不会被补。
- **返回值放宽**：返回值被使用而 Ghidra 写成 `void` 的函数放宽为 `int`（`ret_relaxed`）。
- **全局变量**：`DAT_ram_xxxx` 按 `naming_db.GLOBALS` 换成还原名；同地址的
  `DAT_/ _DAT_` 重叠写法统一。

### 4.1 0xD05A 与 `0x1A15A`（`decc_dispatch`）

`0xD05A` 是十进制运算的**中间状态**，不是输出格式；早期“R4=3/2/1/0 选择
Fix/Sci/Norm”的推断是把 `0x1D1C6..0x1D202` 的公共尾当成格式分派造成的误读。

逐指令核对得到的调用约定：

- `0x1D1C6/0x1D1DA/0x1D1EE/0x1D202` 先 `ST R4,D05A`（分别 3/2/1/0），
  再跳到公共尾 `0x1D214`：`L R4,D05A` 后只判断 `R4 >= 3`，用来选择
  `0x1A4F6`（整数路径）或 `0x1A79A`（BCD 路径），与“输出格式”无关。
- 用 `0x1A15A` 时，`0/1` 进入 `0x1A4F6`；`2/3` 与 `>=12` 进入 `0x1A61A`
  （按操作码选 `0x1C4EE/0x1C670`）。
- `0xD05A` 的全部写入点：`0x1D1C6/0x1D1DA/0x1D1EE/0x1D202`（3/2/1/0）、
  `0x1A79A`（0）、`0x1A6F0/0x1A6FA`（5）、`0x17E18/0x19E00/0x19EF8/0x1A04C`
  （0xF，特殊值路径）。
- `0x1AB54`（阶段 `<9`）是尾数错位对齐（DAA 链），`0x1AC2C`（阶段 `==9`）
  先置 `Y=1.0` 再做带进位对齐；二者只是 `0x1CE4E` 加/减法的两条尾段，
  因此命名为 `decc_addinit` / `decc_rounded_add`，而不是“加法/减法入口”。

### 4.2 矩阵单元编址

`0x14B0A` 返回 `(R12*5 + R13)*10 + ER4`，`0x13AC4` 返回 `(R12*4 + R13)*10 + ER4`，
`0x14314` 取 `t[0]>>4` 作为类型高位。矩阵单元格因此按“行×i 字节”编码，
统计表格的 `T` 列（`0x2A318/0x2A428` 构造的 10 字节描述）复用了同一套宏。

### 4.3 其它新确认

- `0x2196A/0x21970` 的“墓碑”结论保持（见 3.4）。
- `0x2A886`（字符 3 → 1）与 `0x24A14`（字符 2 → 1）成对使用，用于统计表
  分数/混合数输入。
- `0x1A4F6/0x1A79A/0x1A7A4/0x1A920` 属于 DECIMAL 整数路径（`decc_int_*`），
  与 STAT 编辑无关；早期 `stat_edit_*` 名称已撤销。

## 5. 已知限制

- `0x1F12E` 的原始字节码在 `\x7f` 处丢失一个 `0x7F`（应为 `0x7B` = `'{'`），
  导致该函数内层的 `}` 被吞；同理 `0x22006`、`0x23BD6`。原始文本已就地保留。
- 部分函数只有片段（Ghidra 把共享帧的内部块切成了独立“函数”），它们的
  `unaff_ERxx` 实为调用者的栈帧变量，C 中写成占位。
- `docs/还原进度.md` 中 `likely` 级别的名称仍需逐条复核。
