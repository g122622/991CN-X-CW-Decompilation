# fx-991CN X 技术赏析：一台计算器里的小系统

面向有计算机体系结构基础的读者。所有数字与地址都来自本仓库的逆向结果
（`toolkit/naming_db.py`、`rawasm.asm_view()`）与

## 1. 硬件配置

| 项目 | 参数 | 依据 |
|------|------|------|
| 主控 | OKI（现 LAPIS）nX-U8/100 核心的 8 位 MCU，CISC 指令集 | `nX-U8100 Core Instruction Manual` |
| 通用寄存器 | 16 个 8 位寄存器 R0–R15；可两两拼成 ER0–ER14、四个拼成 XR、八个拼成 QR0/QR8 | 手册 §1.2.1 |
| 专用指针 | ER12 = 基址指针 BP，ER14 = 帧指针 FP（C 编译器约定） | 手册 §1.2.1.2 |
| 地址空间 | 代码 16 段 × 64 KB = 1 MB（20 位 CSR:PC）；数据 256 段 × 64 KB = 16 MB（24 位 DSR:AR） | 手册 §1.3.1 |
| ROM | 256 KB flash：段 0 的代码 0x00000–0x0FFFF、段 1 0x10000–0x1FFFF、段 2 0x20000–0x2FFFF、段 3 的数据 0x30000–0x3FFFF | `rom/rom.bin` 大小 0x40000；`代码分析.txt` 的分段表 |
| RAM | 段 0 的数据区 0x0000–0xEFFF（ROM 窗口 0xD000–0xEFFF 之后才是真 RAM） | `内存表.txt`：991CN X 的 ROM_WINDOW = 0xD000 |
| SFR | 0xF000 起：DSR、待机控制、定时器、显示控制、键盘口 | `内存表.txt`、`labels_sfr.txt` |
| 显示 | 198×64 点单色 LCD，显存 0xF800 起 0x800 字节（64 行 × 32 字节，每行 192 列 + 6 位余量） | `lcd_vram` 全局变量注释 |
| 软件栈 | 4 个 10 字节 BCD 浮点寄存器（X/Y/Z/W）+ 200 字节输入区 + 400 字节历史 + 200 字节撤销区 | `命名与还原方法.md` §3.1、`内存表.txt` |

几个值得注意的点：

- **pipelined CISC**：手册说每条指令至少要经过取指、译码、执行三个周期，但流水线让它们并行；
  ROM 窗口访问和 `[EA+]` 寻址会插入等待周期。这解释了为什么反编译出来的代码里
  `LD ER0, DSR:[EA+]` 这类连续块复制的写法特别多——它是这条流水线上最快的搬运方式。
- **ROM 窗口**：段 0 的 0xD000–0xEFFF 在数据地址空间里其实是**只读的 ROM**，用普通 RAM 指令
  就能读常量表（代价是多几个周期）。所以 ROM 里大量数据表都放在 0xD000 以下，而代码直接
  `L R0, 0x1234` 就能取到——这是 nX-U8 对比同期 8051 的一大便利。
- **1 MB 代码空间只用了 256 KB**：`CSR` 只有 4 位，固件只在段 0–2 放代码（段 0 的代码区
  0x00000–0x0FFFF、段 1、段 2），段 3 的数据区 0x30000–0x3FFFF 放表数据和型号字符串、
  校验和。`rom.bin` 共 0x40000 字节，其中约 85 KB 是 0xFF 填充。

## 2. 启动流程

### 2.1 向量表（0x00000–0x000FF）

```text
0x0000  F000        初始 SP
0x0002  93FE        外部复位 / BRK(ELEVEL≥2) 入口
0x0004  9400        BRK(ELEVEL<2) 入口
0x0006  0060        NMICE（模拟器中断）
0x0008..001E  EC93 ×12   NMI 向量
0x0020..007E  ...        MI 向量（29 个）
0x0080..00FE  ...        SWI #0..#63 向量
```

`0x93FE` 是一段只有 2 条指令的门：`BC AL, 0x9402`——**条件置位才跳，否则原地死循环**。
`BC` 的条件码 `AL` 在 nX-U8 上是“无条件”，但 `BC` 同时会先做一次比较，Ghidra 把这里
误读成了普通函数（`docs/反编译结果已知缺陷.md` §1）。

### 2.2 冷启动（0x9402 `reset_entry`）

```text
MOV R10, #2 ; LEA 0BEE6h      ; DSR <- 2（段 2），EA 指向初始化表
循环：
  L ER0, [EA+]  → SRAM 地址（被复制到 RAM 的地址）
  CMP R0,#FFFF; EQ → 结束
  L ER2, [EA+]  → 源地址（段 2 内偏移）
  L ER4, [EA+]  → 长度
  ...按奇偶选择 2 字节或 1 字节循环搬运...
结束：
  BL 0xB90A      ; 空的 RT 桩（可能是早期版本的钩子）
  MOV R0,#0; ST R0,F000h   ; DSR <- 0
  B 0x24E36      ; main
```

初始化表就放在段 2 的 0xBEE6 处，以 `FFFF` 结束。每个表项 8 字节：

```text
+0 目标地址（RAM，字）      L ER0, [EA+]
+2 源地址（段 2 偏移，字）  L ER2, [EA+]
+4 长度（字数）             L ER4, [EA+]
+6 未使用（源码里被读入 R6/R7，但从不使用）
```

条目长度是 0 时跳过。搬运时按目标/源地址的**奇偶**选择字复制（`ADD ER4,0` 之后
`BC EQ`）或字节复制：地址都是偶数就用 `L ER8 / ST ER8` 一次搬 2 字节，否则退化为 1 字节。
段选择通过 `DSR <- 2` 一次设置，之后一直用 `[EA+]` 自增寻址。

> 注意：段 0 代码区的 0xD000–0xEFFF 是 ROM 窗口，所以初始化表里能看到“源地址看起来像
> 段 2 的 RAM 地址”的项（如 0xFC46）——Ghidra 把段 2 的偏移当成了 3 字节 SRAM 地址。
> 实际上 `DSR=2` 时，0xFC46 是**段 2** 在 ROM 中的 0x2FC46 附近，而不是 RAM。
> 这一点仍需逐项用 ROM 字节确认（见 §5 的待办）。

### 2.3 main（0x24E36）

`main` 先依次调用：

1. `0x9242` 初始化系统（时钟、SFR）；
2. `0x90CE` RAM 有效性检查——失败则全清。它在 0xDBD0 处写/校验
   `0F 0E 0D … 02 01 00` 这 16 个字节，像是一块“内存指纹”；
3. `0x8CEE` 模式界面初始化、`0x8CE…` 存储/显示初始化；
4. `0x2250E / 0x22006 / 0x22040 / 0x10E9C` 自检与显示复位；
5. 进入无限循环：读 0xD111（模式字），分派到各模式的顶层循环。

### 2.4 初始化表的实际布局（逐字节核对后修正）

初看反编译代码会以为每项 8 字节（`ER0/ER2/ER4` 外加 `R6/R7`）。但把 `rom.bin` 的段 2
（0x20000 起）按 6 字节一项读出来是：

```text
0x2BEE6: 00 00  00 00  00 00   目标 0x0000, 源 0x0000, 长度 0
0x2BEEC: FF FF  FF FF  FF FF   结束标志（长度为 FFFF？）
0x2BEF2: FF FF ...              其后全是 FFFF
```

也就是说，**初始化表在真机 ROM 里是空的**：第一项长度为 0（搬运循环直接跳过），
第二项立即命中 `0xFFFF` 结束标志。`R6/R7` 的读取只是循环体里的“第 4 个 16 位值”，
它没有对应的表字段——是 Ghidra 把 `[EA+]` 链的边界判错了。

这说明：**冷启动并不从 ROM 复制任何数据到 RAM**，所有 RAM 状态都由 `main` 里的
`ram_clear_all`(0x1F99C) 与后续初始化（内存指纹 0xDBD0、默认设置 0xFFC0 等）重新建立。
对逆向的意义是：RAM 快照不能从 ROM 初始化表推导，必须走 `main` 的初始化路径。

### 2.5 完整性自检

0x3FFF6 处存着 `A8 04`。`diag_calc_checksum`（0x22392）的计算方式是：写 `0xF004=1`，
然后从段 5（`DSR <- 5`）开始，每读一个 16 位字就 `SUB R8,R10 / SUBC R9,R11`，
依次扫过段 5、1、2、3，最后与 `0x3FFF6` 估算出的“负数和”比较。`参考-casio-main/checksum.py`
给出了同一算法的 Python 版本，并验证对真机 ROM 结果为 `0x04A8`。

> 有趣的是：段 5 在 256 KB 的 ROM 里**并不存在**，但 nX-U8 的高段可能映射到内部或调试
> 空间，自检读取它后再相减，等于把“未映射区读出的值”也纳入校验——这也可能是一种
> “若读到 0xFFFF（总线浮空）也能被发现”的防御性设计（推测）。

## 3. 主要功能的实现

### 3.1 输入与显示：一切皆字节

**输入区**（`0xD180`，200 字节）里存的不是文本，而是**记号流（token）**：
每个数字/运算符 1 字节，函数/双字节字符 2–13 字节，`0x01` 表示换行/占位，`0x04` 表示
“无宽度前缀”（数学格式里的分数/根号），`>=0xF0` 是双字节字符头。
- 输入上限 199 字节，剩 10 字节时光标变宽——这就是你在说明书里看到的“光标形状变化”；
  固件在 `input_max_len`(0x9B6E) 里返回 200 / 0x32 / 0x31 三种上限。
- `0xD247` 是输入区结束符，`0xD248` 起 199 字节是**回放区**（replay buffer）：
  按 `=` 时把输入区复制过来，没输入时按 `←/→` 又复制回去。

**显示**走两套缓冲：

| 缓冲 | 地址 | 用途 |
|------|------|------|
| 主帧缓冲 | 0xDDD4 | 完整屏幕（64 行 × 24 字节） |
| 副帧缓冲 | 0xE3D4 | 小字体/状态行等局部绘制 |
| LCD 显存 | 0xF800 | 直接驱动 LCD 的 0x800 字节 |

绘制流程是“字形缓冲区 → 帧缓冲 → LCD”：`draw_char`(0x82F6) 取字形后逐位 OR 进帧缓冲，
`fb_flush`(0x8704) 再把整帧推到 LCD。`0xD139` 决定当前画到哪块缓冲，
`0xD137` 是字号（8/10/14 像素）。14 像素字体时每字符宽 11 像素，8/10 像素时宽 6 像素——
`line_print`(0x821E) 里那句 `R13 = (font_size==14 ? 11 : 6)` 就是宽度计算。

### 3.2 十进制运算：BCD 的“微架构”

nX-U8 **没有浮点单元**，甚至没有 16 位乘法器以外的数学硬件。`fx-991CN X` 的 15 位精度
全部由软件实现，核心是一套以 10 字节 BCD 寄存器为基础的“十进制协处理器”：

```text
X 0xD000..0xD009   主累加器
Y 0xD010..0xD019   操作数 2
Z 0xD030..0xD039   操作数 3
W 0xD050..0xD059   返回槽
0xD01E             运算操作码
0xD01F             运算阶段
0xD05A             中间状态
```

每个寄存器：2 字节类型/符号、7 字节打包尾数、2 字节指数。

**分派层次**很清晰：

1. `decm_*`（0x1CD78–0x1CE3C）是 11 个薄封装，把 `R4`（操作码）和 `R5`（族：9=乘方、
   10=三角函数、11=加减）传给总和入口 `0x1CE4E`；
2. `0x1CE4E` 按族分派：加减族按 `0xD01F` 阶段调用 `0x1AB54`（阶段<9，尾数错位对齐）
   或 `0x1AC2C`（阶段=9，置 Y=1.0 后做带进位对齐）；
3. 更底层还有 `decc_dispatch`（0x1A15A）与二进制核心 `dec_bin_dispatch`（0x1CFA4）两级分派。

**DAA 链**是这里最精彩的地方：nX-U8 的 `DAA` 指令只调整一个字节的 BCD 加法结果，
`0x1AB54`/`0x1AC2C` 用 `ADD`/`SUBC`/`DAA` 组成多字节 BCD 加法和“错位对齐”，
把两个不同指数的尾数逐字节对齐后相加——这是一台 8 位 MCU 上手工搭出来的十进制 ALU。
（两个函数的说明见 [`casio-main符号对照.md`](casio-main符号对照.md) §5 与函数索引 0x1AB54 / 0x1AC2C。）

三角函数怎么实现？`0x1CAA6` 装载操作数后调用 `0x19B28`（`xln x`），再按阶段选 `e^x`
（0x1B1E8）或乘方核心——即 **sin/cos/tan 通过指数/对数抽象出来**，而不是查表。

### 3.3 模式与界面

`0xD111` 一个字节存放当前模式，`0xEE2A` 的 7.4 KB 主循环按它分派：

| 模式字 | 模式 | 主循环 |
|--------|------|--------|
| 0x02 | COMP（计算） | `0x9D94 mode_02_comp_loop` |
| 0x03 | TABLE（表格） | `0x29B58 mode_03_table_loop` |
| 0x06 | STAT（统计） | `0xD968 mode_06_stat_loop` |
| 0x45 | BASE-N（基数） | `0xDC66 mode_45_base_loop` |
| 0x4A | 方程/函数 | `0xB810 mode_4a_eqn_loop` |
| 0xC1/0xC4/0x88/0x4B | COMP/复数/比例/不等式 | 由菜单路由 `0x28C10` 进入 |

每个模式都有自己的编辑循环：`editor_main`(0x29614, 11 KB) 是通用的输入编辑器，
`table_edit_main2`(0x27284, 9.4 KB) 和 `stat_main_loop`(0x256E0, 12 KB) 是表格/统计专用。

### 3.4 键盘与“时钟节拍”延时

键盘通过 SFR `0xF040`（KI，输入，低电平有效）和 `0xF046`（KO，输出扫描）访问。
`kbd_ko_set`(0x8CAE) 把 KO 全拉低，`kbd_ko_disable`(0x939A) 清零。
读键 `read_key`(0x1F574)：根据 `0xD110`（修饰键状态）驱动 KO 编码，再查模式相关的
键位映射表（`keytab_*`，每个模式一张 64 项表）。

延时 `delay`(0x916A) 不用循环空转，而是**写定时器 SFR 后进入 STOP 模式**：
`0xF008=0xA0`、`0xF009=2`、`0xF020=interval`，由定时器/键盘中断唤醒——这是电池供电
设备省电的关键。

## 4. 令人惊叹的技术细节

### 4.1 在只有 BCD ALU 的芯片上实现科学计算器

15 位十进制、指数范围 1e-99…1e99、精度“第 10 位 ±1”——这一切由约 300 个函数组成的
十进制数学库实现，而硬件只提供 8 位加减、移位、`DAA`/`DAS`。ROM 里约 64 个 `float`
标签函数 + 286 个 `bcd` 标签函数，构成了完整的初等函数、统计、矩阵、方程求解能力。

### 4.2 “墓碑函数”：编译器生成、但看不见代码的辅助

0x2196A / 0x21970 只有 2 条有用指令：

```asm
R1 = 0 ; ADD ER0, ER8 ; RT     ; 测试 *ER8 的某位
R3 = 0 ; ADD ER2, ER8 ; RT     ; 清除 *ER2 的某位（写回 0）
```

它们被全 ROM 调用约 90 处，作用是**用 ALU 的零标志完成“读-比较”和“读-清零”**，
而不占用额外指令周期去 `L`/`CMP`。Ghidra 看不到数据流，把前者写成
`(ushort)param_1 + unaff_ER8`、后者写成空函数——这是理解 nX-U8 编译器技巧的典型样本。

### 4.3 用绝对地址做参数传递

大量函数在调用后立刻从 `unaff_ER14 + N` 读值：Ghidra 把它们标成“未初始化变量”。
实际上这是编译器把**栈帧地址**当成隐式参数传给子函数——nX-U8 的 `Disp6[FP]` 寻址
让子函数可以直接访问调用者的局部变量（类似“父帧指针”）。本工程统一把这些
`unaff_ER14` 改成 `fp` 并加注释。

### 4.4 已知缺陷与逆向修正

Ghidra 的文本有三类“写窄/写残”的指令（例如 `0xD85E` 的 `01` 实际是
`01 F2 82 2B` 的 `BL`），本工程通过 casio-main 的注释反汇编逐字节补齐，
最终 **59914/59988 条（99.88%）与参考一致**；剩余 74 条全部可解释。
详见 [`casio-main符号对照.md`](casio-main符号对照.md) §5。

### 4.5 ROP：在计算器上执行任意代码

把输入流中的特殊字符当作垃圾字节注入，跳转到 ROM 中的 `gadget`，就能在真机上执行
任意代码。仓库的 [ROP](../../../ROP) 目录与 [rop_disas](../../../rop_disas) 提供了
示例程序与汇编器；`参考-casio-main/gadgets.txt` 列出了 `pop qr0`、`[er0] = r2`
这类“找到就中奖”的短序列。这也是为什么本工程坚持给每个函数、每张数据表起名：
ROP 的每一步都需要精确的地址与语义。
